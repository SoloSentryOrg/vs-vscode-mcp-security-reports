# Security Policy

## Report a vulnerability or sensitive-content concern

Do not open a public issue containing vulnerability details, credentials,
personal data, private paths, or other sensitive information.

Use GitHub's **Security** tab and select **Report a vulnerability** to submit a
private vulnerability report. Include:

- the affected report and version;
- the page, section, or file path;
- the concern and potential impact;
- safe reproduction or verification information; and
- whether coordinated disclosure or an embargo is required.

If private vulnerability reporting is unavailable, contact the repository
maintainer through their GitHub profile without including sensitive details in
a public message.

## Supported material

The current report versions listed in `reports/index.json` receive correction
and sensitive-content review. Historical versions remain immutable public
records and may be superseded by a corrected version.

## Response

Reports are assessed individually. Confirmed public-data exposure may require
temporarily making this repository private while containment and publication
history are reviewed.
